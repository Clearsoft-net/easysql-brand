## 🎨 Official Color Palette

### Brand Gradient ("E" Monogram Tile)
The gradient visually connects EasySQL to its parent company, [Clearsoft](https://clearsoft.net):
* **Start:** `#F97316` (Orange)
* **End:** `#F472B6` (Pink)
* **Letter "E":** `#FFFFFF` (White)

### Typography & Text
* **Dark Mode:** `#F1F5F9` (Slate 100)
* **Light Mode:** `#0F172A` (Slate 900)
* **Secondary text:** `#94A3B8` (Dark) / `#64748B` (Light)
* **Wordmark accent ("SQL"):** `#F97316` (Orange), in both modes
* **Wordmark type:** Space Grotesk Bold (700) for "Easy", Geist Bold (700) for "SQL"; the "E" monogram stays Inter ExtraBold
* **Light background:** the orange "SQL" is intended for display sizes; use the monochrome lockups for small sizes or one-color/print reproduction.

### Recommended Backgrounds
* **Dark Background (Product):** `#0F2B3D` (Petroleum Blue) or `#0B1E2B`
* **Light Background:** `#FFFFFF` or `#F8FAFC`

WebP is the default for loaders: it works as an `<img>`, loops natively and keeps alpha (Safari 16+). GIF is a 256-color/1-bit-alpha compatibility fallback. Pause or swap the animation when `prefers-reduced-motion` is set. Regenerate with `make animated`; `make check-animated` validates dimensions, frames, loops and alpha.

[Open the loader showcase](./index.html#loaders) to compare every variant on dark and light backgrounds.

The animated files run at 1.2 s (01, 04), 1.8 s (02), and 1.4 s (03, 05). Use `<picture>` to swap the static poster when `prefers-reduced-motion: reduce` matches; browsers do not consistently apply the media query inside an SVG loaded as `<img>`. Pair the loader with a text status (`role="status"`) and keep one loader per view. Never recolor the gradient, add shadows/glows, rotate the E, or use the wordmark as a spinner. On white, prefer the monogram loaders (02, 05) or the monochrome lockups; the gradient strokes are intended for the product dark backgrounds.

Static posters are generated from the animated SVGs with `make loaders` (also run by `make`); `make check` fails when a poster is stale.

## 🛠 Source vs. Exports

- **`logo/source/` and `icon/source/`** — editable text sources. Edit here, then run `make outline`. The `-bg` sources use the distribution crop viewBox so the opaque canvas matches the export; the other logo sources keep the design viewBox.
- **`logo/exports/svg/` and `icon/exports/svg/`** — outlined, self-contained SVGs. Logo SVGs are cropped to the artwork with an 8 px transparent border at 1× (same canvas as the 1× PNG); icon SVGs keep the full canvas. These are the files linked below and the input for every export; they render identically without the fonts.
- **`logo/exports/`, `icon/exports/`, `social/exports/`** — generated files: PNGs (1×/2×/3× for logos, absolute sizes for icons), multi-resolution ICOs, the web platform set, the macOS ICNS, and the social cards. Do not edit these by hand.
- **`loaders/`** — self-contained animated SVGs; **`loaders/static/`** holds the generated posters used for `prefers-reduced-motion`, and **`loaders/exports/`** the generated GIF/WebP formats. They contain no live text and do not go through `make outline`; run `make loaders` and `make animated` after editing an animated file.

## 🔨 Building

`make` requires ImageMagick 7 (built with librsvg) and Python 3.8+. Regenerating the outlined SVGs with `make outline` additionally requires HarfBuzz (`hb-shape`), fontTools, and the Inter, Space Grotesk, and Geist fonts (all on Google Fonts).

| Command | Output |
|---|---|
| `make outline` | Rebuild `logo/exports/svg/` and `icon/exports/svg/` from the editable `source/` files |
| `make loaders` | Generate the static loader posters in `loaders/static/` |
| `make animated` | Export GIF and WebP into `loaders/exports/` (requires Node, Chrome and FFmpeg) |
| `make` | Regenerate the core, platform and social exports, rebuild the loader posters, and run `make check` |
| `make logos` | Logo PNGs at 1×, 2×, and 3× |
| `make icons` | Icon PNGs from 16×16 to 1024×1024 |
| `make ico` | Windows ICOs (16–256) |
| `make platform` | favicon, PWA, maskable, Apple touch, and Android set |
| `make macos` | `AppIcon.icns` |
| `make social` | Open Graph card and social avatar in `social/exports/` |
| `make check` | Validate rasters, platform layers, social cards, ICO/ICNS frames, and loader structure/posters |
| `make check-animated` | Validate animated loader dimensions, frames, loops and alpha (requires `ffprobe`) |
| `make clean` | Delete generated exports, social cards, loader posters and animated formats (regenerate afterwards) |

Animated formats are generated separately: `make animated` needs Node 22+, Chrome/Chromium and FFmpeg; `make check-animated` needs `ffprobe`.

An SVG user unit is a CSS pixel at 96 dpi; the build script derives every density from the target pixel size. Outputs are byte-reproducible (date chunks are excluded from the PNGs).

Logo exports are cropped to their artwork: `make outline` writes the distribution SVGs with the viewBox trimmed to the content plus an 8 px transparent border at 1× (261×88 horizontal, 145×130 stacked, 181×53 wordmark), and the PNGs repeat the same crop with `-trim +repage -bordercolor none -border 8` at 1× — the border scales to 16 px at 2× and 24 px at 3×. The editable sources keep their design viewBox. Icon exports keep the full canvas because their sizes are absolute.
